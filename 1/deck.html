01 · WHAT IS IT

不用填资料，数据替你说话

用户不费劲填资料。我们从多邻国、Keep 这类第三方 App 拉取真实行为数据自动生成标签；匹配时双方只看到一个百分比，看不到照片、年龄、学历。想知道对方是谁，就得聊下去。

  • ①

    真实数据接入

    多邻国学习天数、Keep 运动记录自动成标签，不是用户自填。

    解决 · 不可信
  • ②

    匿名匹配

    只给匹配度，不给照片与标签明细。属性从一堆参数收敛成一个数字。

    解决 · 选择悖论
  • ③

    破冰工具箱

    摇骰子、抽任务卡、解锁匹配点。把「我该说什么」变成「按提示做」。

    解决 · 破冰难
  • ④

    线下兴趣饭局

    3–10 人局替代 1V1 见面，钩子是共同兴趣而非颜值。

    解决 · 无线下出口

前三个解决线上「信不信、怎么选、聊什么」，第四个解决线上关系怎么落到线下。

02 · WHO

两侧用户，一套标签

C 端用户 · 5 类典型诉求

  • 找垂直搭子「找个学英语的搭子每天陪我说 10 分钟」
  • 想认真聊天「我要精神层面的匹配，不是看颜值」
  • 社恐 / 不会破冰「加上好友第二天就沉了」
  • 想线下认识同频人「想认识做 AI 的人，但不想一对一相亲式吃饭」
  • 新到一个城市「刚来上海，周末不知道跟谁吃饭」

B 端餐厅 · 商业闭环

  • 中小餐厅 / 咖啡馆「周二到周四晚上空一半桌，愿意打折换客流」
  • 有主题氛围的店「我想把店做成 AI 从业者常来的地方」

三方都有收益

餐厅出让一部分利润换真实客流，平台提供成团能力与精准人群，用户拿到折扣。这是本产品区别于纯社交产品的地方。

03 · WHY NOW

市面产品的四个断点

  1. 01

    资料全靠自填，真实性没法验证

    写「热爱运动」「正在学日语」没有任何成本，也没有任何证据。用户有强烈的验证需求，产品没给抓手。

  2. 02

    刷卡片放大颜值学历，反而更难决定

    选择悖论：可选项质量提升不会提高满意度，只会不断抬高标准。看得越多，越挑，越不满意。

  3. 03

    陌生人破冰极难，匹配即终点

    匹配成功不等于关系开始。没有共同话题，双方都在等对方先说，绝大多数会话止于前三句。

  4. 04

    1V1 dating 垄断，线下没有低压入口

    一对一见面压力极大、全程互相审视、聊崩了没有退路。真实需求是认识一群同频的人，不是找对象。

06 · MODULE ②

权重是后端参数，不是用户功能

100% 按比例分配到各标签，写在统一配置文件里。用户端没有任何权重配置入口：没有配置页、没有滑块、没有拖拽格子。

  • 交友目的30%自填 · 目的不一致，其他维度再像也聊不下去
  • API 行为标签25%多邻国 / Keep · 差异化卖点必须有话语权
  • 兴趣爱好20%自填 · 共同话题的直接来源
  • 活跃时间重叠度15%自填 + API 复合 · 隐性但强相关
  • 城市5%匿名线上为主，同城不是刚需
  • MBTI5%弱信号，只做微调

兜底规则

未授权任何第三方 App 时，行为标签的 25% 按 30:20 回补到交友目的与兴趣爱好 → 交友目的 45% + 兴趣爱好 30% + 时间重叠 15% + 城市 5% + MBTI 5%。

研发要求

权重集中在 matchWeights.config.ts，禁止散落硬编码；预留 groupKey 对应交友目的；启动时断言各组权重之和等于 1。

06 · MODULE ② · ALGORITHM

匹配度计算四步

  1. 第一步

    硬性过滤

    按年龄区间、希望匹配性别过滤候选池。

    不占权重
  2. 第二步

    逐标签打分

    对候选池每个用户计算 sim_i ∈ [0,1]。

    6 种类型
  3. 第三步

    加权求和

    匹配度 = Σ(w_i × sim_i) × 100%，其中 Σw_i = 1。

    合计 100%
  4. 第四步

    展示平滑

    原始分映射到 60%–98% 区间后展示，避免 12% 这类挫伤体验的低分。

    排序仍按原始分
六种标签类型的相似度算法
标签类型举例相似度算法
枚举型城市、星座、作息完全相同 = 1.0 ｜ 同大类不同项 = 0.5 ｜ 无交集 = 0
多选枚举型兴趣爱好、交友目的Jaccard = 交集数量 / 并集数量
数值型打卡天数、周运动频次1 − |A−B| / 归一化上限，下限截断为 0
时段型学习 / 运动活跃时段重叠小时数 / 并集小时数
分级型坚持度、运动强度1 − |等级差| / (总等级数 − 1)
MBTIINFP / ENTJ4 个字母逐位比较，相同位数 / 4

06 · MODULE ② · SEARCHING

三阶段过程动画，状态机在服务端

  1. 260ms硬性筛选年龄区间 · 希望匹配性别
  2. 1000ms相似度计算逐标签 sim_i 打分
  3. 1740ms匿名排序按原始分排序
  4. 2500ms完成POST /matches/search/complete

前端只管时序

match-flow.js 只控制展示时序与提交普通 POST 表单。候选选择、尝试令牌、取消、旧页面失效、结果确认全部由 Flask session 状态机处理。

降级路径

无 JavaScript 时可直接提交「查看结果」；prefers-reduced-motion 下立即完成步骤并进入服务端结果。匹配中 HTML 不含候选 ID、代号、分数、标签或结果 JSON。

10 · DESIGN SYSTEM

玩具箱风格：亮黄 + 黑描边 + 硬投影

产品数据源是多邻国，破冰工具是骰子、任务卡、大富翁，本身带强游戏基因。这套视觉让工具箱不用解释就显得好玩。

  • --surface#FFFFFF卡片面板
  • --surface2#FFE95C标志性亮黄
  • --text#17150F文字与描边
  • --primary#5B4DFF主按钮 · 焦点环
  • --accent#58CC02进度 · 成功
  • --hot#FF5A36券 · 商家 · 警示

三条设计原则

  • 边界要硬每个可交互元素都有黑描边和实心投影，一眼看出「这能点」
  • 颜色要少一屏最多两种强调色，黄色只做高亮不做大面积底
  • 数字要大匹配度、天数、人数用最大字号最重字重，是视觉主角

暖白 60%黑 25%黄 10%5%

对比度实测 · WCAG 公式验算

  • #17150F on #FFE95C14.83:1AAA · 黄底必须配黑字
  • #FFFFFF on #5B4DFF5.32:1AA · 主按钮白字可用
  • #FFFFFF on #58CC022.09:1禁止绿底白字
  • #17150F on #58CC028.74:1AAA · 绿底必须配黑字
  • #58CC02 对底色2.03:1焦点环用紫不用绿
10 · DON'TS

硬投影是灵魂，加模糊就塌了

  • 投影加模糊半径硬投影是风格识别特征，加模糊就变成普通卡片
  • 亮黄做大面积背景黄对底色只有 1.20:1，大面积会廉价刺眼
  • 绿底配白字对比度 2.09:1，明确不达标
  • 绿色做焦点环对底色 2.03:1，看不清
  • 渐变 / 毛玻璃 / 发光与风格冲突，也拖慢实现
  • 第三种强调色一屏最多两种强调色
  • 描边随元素大小变化统一 2.5px 才有整体感
  • 无边框幽灵按钮违反「边界要硬」，用户看不出能点

交互态位移 · 手感来源

hover translateY(-2px)，投影缩到 3px 4px 0 —— 浮起来

active translate(3px,4px)，投影归零 —— 被压到底

选中 底色换亮黄，描边与投影不变

禁用 亮黄换 #EFEDE4，去掉投影

动效时长与曲线
场景时长曲线
hover / 按下位移140msease
「？」卡翻开260ms回弹 .34,1.56,.64,1
骰子旋转450msrotate(360deg) scale(1.3)
进度条增长500msease

所有「高级感」都由描边和硬投影承担。必须支持 prefers-reduced-motion: reduce，命中时关闭位移与旋转，只保留颜色变化。

11 · SCOPE

P0 缺一个，Demo 就不成立

  2. 数据接入：mock 实现 + 真实接口抽象层 → 20+ 标签
  3. 匹配算法：硬性过滤 + 统一权重配置表 + 逐标签打分 + 展示平滑
  4. 匹配结果页：仅百分比 + 「？」匹配点
  5. 匿名聊天：文字 + 系统卡片消息
  6. 破冰工具箱：摇骰子、抽任务卡、匹配点解锁
  7. 关系进度条：至少跑通 L0 → L1 → L4 演示路径
  8. 约饭 C 端：发起表单 + 广场排序 + 成团流转 + 群聊
  9. 约饭 B 端：活动展示 + 发券 + 静态核销码
  10. 先落地 :root CSS 变量，再写组件，避免返工

  • #3

  • #4

13 · RISK

已识别风险与应对

  • 线下饭局的人身安全

    一旦出事对产品是致命打击

    强制真实餐厅 POI、实名门槛、性别构成透明、举报入口、支持仅同性别局

  • 匿名 + 真实数据的隐私合规

    上线风险

    明确授权弹窗、数据最小化采集、标签仅本人可见

  • 多邻国 / Keep 是否有开放接口

    影响「真实性」核心卖点的说服力

    优先验证；接不通用 mock，话术讲清接口已抽象预留

  • 匹配度分布过低，观感差

    用户看到 20% 直接流失

    展示层平滑，收敛到 60%–98%

  • 解锁周期 7 天无法真实演示

    评委看不到完整链路

    提供演示模式，可手动跳阶段

  • 约饭冷启动，广场空

    用户进来没有局可报

    B 端活动兜底 + 预置 mock 活动；初期限定 1–2 个城市

  • 成团失败率高

    体验挫伤

    下限 3 人、截止提前 2 小时、未成团自动取消通知；P1 补信誉分

  • 中文字体整包拖慢加载

    首屏白屏，路演现场卡顿

    标题用 PingFang SC 加粗顶上，Archivo 只走拉丁子集
